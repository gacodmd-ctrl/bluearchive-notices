# 블루아카이브 공식 공지 알림

한국·일본 공식 홈페이지의 새 글을 Discord 공지 채널로 전달합니다. GitHub Actions가 클라우드에서 실행하므로 개인 PC를 켜 둘 필요가 없습니다.

- 한국: 넥슨 공식 커뮤니티 공지사항, 업데이트, 개발자 편지, 상점 안내, 진행 이벤트, 당첨 안내
- 일본: 일본 공식 사이트의 점검·공지·이벤트 뉴스
- 새 글마다 국가 표시, 제목, 공식 원문 링크와 `블루아카이브` 역할 멘션
- 약 30분마다 확인(매시 23분, 53분). GitHub 사정으로 지연될 수 있으며 실시간 전송은 보장하지 않습니다.
- 첫 실행에서는 기존 글을 기록하고 과거 공지를 일괄 전송하지 않습니다.
- 같은 게시물의 본문 수정은 재전송하지 않습니다. 새 게시물만 대상입니다.

## 설정

저장소 **Settings → Secrets and variables → Actions**에 `DISCORD_WEBHOOK_URL` Secret을 등록합니다. 웹훅 주소를 코드, 이 문서 또는 로그에 넣지 마세요.

역할 ID: `1561292516970602539`. 알림을 받을 멤버에게 해당 역할이 부여되어 있어야 합니다. 실제 알림 수신은 개인의 Discord 알림 설정에도 영향을 받습니다.

**Actions → Blue Archive official notices → Run workflow**에서 수동 실행할 수 있습니다. `send_test`를 켜면 최초 한 번 연결 테스트를 보냅니다. 예약 실행을 중지하려면 해당 workflow의 메뉴에서 **Disable workflow**를 선택하세요.

## 운영

`state.json`은 이미 처리한 공지와 전송 결과를 보관합니다. 삭제하면 첫 실행 기준으로 다시 초기화하므로 유지하세요. 전송 실패 시 실패한 공지를 완료로 기록하지 않습니다. 네트워크 장애 등으로 전송 결과가 불확실하면 `uncertain`을 남기고 해당 공지 목록의 발송을 멈춥니다. 이 경우 채널에서 해당 공지를 확인한 후, 발송됐다면 그 ID를 `seen`에 추가하고 `uncertain`을 제거하세요. 미발송이 확인되면 `uncertain`만 제거하면 됩니다. 다른 국가·게시판의 확인은 계속됩니다.

GitHub에 상태를 저장하기 전 실행이 중단되면 중복 가능성이 있으므로 Actions 실패 알림을 확인하세요. 공식 사이트의 응답 형식이 변경되면 수집기 수정이 필요할 수 있습니다.

비공개 저장소는 계정의 GitHub Actions 포함 사용량을 소비합니다. 유료 플랜이나 추가 예산을 활성화하지 않습니다. 사용량을 소진하거나 계정 제한이 발생하면 예약 실행이 멈출 수 있습니다.

## 검증

`node --test notifier.test.mjs` — 중복 방지, 역할 제한, 일본 제목 추출, 잘못된 응답, 전송 실패 처리 검사.

`node notifier.mjs --preview` — 공식 사이트 수집 확인만 수행하며 Discord에 전송하지 않습니다.
